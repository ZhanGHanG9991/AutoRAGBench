# Baselines

The baselines of the paper (Section V-C), grouped as in the paper. Every baseline is delivered the same way as an
agent's system: a workspace whose `submission/start.sh` serves `POST /retrieve` on the task corpus, frozen and then
evaluated by `slurm/run.sbatch` with the same evidence extraction, validation, packing and five answering models.

| Folder | Paper name | What it is |
|-|-|-|
| `closed_book/` | Closed-book | `/retrieve` returns no evidence; the answering models rely on parametric knowledge |
| `naive_bm25/` | Naive BM25 RAG | ~200-word passages, BM25, top five passages; also the score assigned to runs that fail the anti-cheating checks after a rerun |
| `reference_rag/` | Reference RAG | BM25 + bge-base-en-v1.5 dense retrieval fused with reciprocal rank fusion, bge-reranker-base reranking; on multi-hop tasks one follow-up query generated by Qwen3.5-4B |
| `human_sota/` | Human-SOTA | thirteen recent human-designed RAG methods adapted to the benchmark interface (below) |
| `automated_rag/` | Automated RAG baselines | Agentic AutoRAG and FlashRAG (Section VI-H) |

`ragcore.py` is the retrieval core shared by `naive_bm25/` and `reference_rag/`; `scripts/new_run.sh` copies it into
the workspace. Run a baseline with

```bash
bash scripts/new_run.sh ref-hotpotqa hotpotqa $RAGENG_ROOT/baselines/reference_rag   # closed_book | naive_bm25 | reference_rag
sbatch ... slurm/run.sbatch ref-hotpotqa reference_rag
```

## Human-SOTA

Each method is adapted from its official implementation: graphs and indexes are built from the task corpus, web
search is disabled, the designated generation model (Qwen3.5-4B behind the metered gateway) is the only LLM at test
time, iterative retrieval is capped at the per-question budget, and `/retrieve` returns the corpus passages the
method selects. Each method had a 24-hour development limit per task. The composite Human-SOTA row of Table II takes,
per task, the highest score of any of these methods.

| Direction (paper) | Folder | Method |
|-|-|-|
| Graph-based indexing | `human_sota/graph_indexing/hipporag2/` | HippoRAG 2 |
| | `human_sota/graph_indexing/lightrag/` | LightRAG |
| | `human_sota/graph_indexing/linearrag/` | LinearRAG |
| | `human_sota/graph_indexing/lego_graphrag/` | LEGO-GraphRAG |
| | `human_sota/graph_indexing/clue_rag/` | Clue-RAG |
| Knowledge-graph subgraph retrieval | `human_sota/kg_subgraph_retrieval/subgraphrag/` | SubgraphRAG |
| Hierarchical indexing | `human_sota/hierarchical_indexing/raptor/` | RAPTOR |
| | `human_sota/hierarchical_indexing/bookrag/` | BookRAG |
| Query rewriting and retrieval control | `human_sota/query_rewriting_retrieval_control/hyde/` | HyDE |
| | `human_sota/query_rewriting_retrieval_control/crag/` | CRAG |
| | `human_sota/query_rewriting_retrieval_control/adaptive_rag/` | Adaptive-RAG |
| Automatic tuning of RAG configurations | `human_sota/automatic_tuning/hammer/` | HAMMER |
| | `human_sota/automatic_tuning/carrot/` | CARROT |

Each method folder has a `README.md` (upstream repository and commit, what was adapted, evaluated tasks, how to
rebuild), `service/` (the code that serves `/retrieve`), `build/` (index construction, training and workspace
assembly), `patches/` when upstream files were changed, and `UPSTREAM_LICENSE`. The upstream code itself is not
copied: install it at the named commit. Code shared by several methods is in `human_sota/_common/`.

Methods used as starting packages in Section VI-G ("Improving Human-Designed Methods") have a `starting_package/`
folder with the package the agents received.
